# MLX T2S 审计后验收边界

执行顺序按项目负责人最新要求收敛：先完成优化设计和实现，每项用小规模测试
检查正确性与基本稳定性；最后两步再集中做 Mac 速度测试和音质验收。
下文的完整测量指标是最终验收参考，不作为每次修改的前置门槛。
批量 Windows 音频预筛已中止；未完成的一键编排草稿保留在本地诊断目录，
不进入当前优化交付。

开发环境是 Windows，没有可用的 Apple GPU。本轮修订的目标是完成优化实现
和小规模检查；Mac 速度测试与音质验收放在最后两步。
任何 Mac 加速结论必须来自真实 Metal/MPS 数据。Torch 仍是产品默认，MLX
保持实验状态；测试成功不自动修改产品配置或批准合并。

## 对审计证据的处理

- 转换器保留源 FP16；原来的 FP32 膨胀发生在模型加载阶段。77,606,402 个
  参数占用约 148.02 MiB（FP16）或 296.04 MiB（FP32）。这是参数数组占用，
  不是整个进程内存，也不是实测每 token 内存读取量。
- 历史五个受控 CPU 配对中，同样的语义 token 下，MLX 语义阶段慢约
  30%–81%。此前五次微基准中“decode 快约 14%”撤回为加速证据，原始数据
  保留，不能用改写摘要代替数据。
- FP16 源权重升为 FP32 不增加权重信息，但会改变计算精度。选择 FP16
  必须检查 logits、生成分歧和真实音频，不能只比较参数字节数。
- MLX 0.32.2 的 Metal SDPA 对 head_dim=32 走分解路径。
  [锁定版本实现](https://github.com/ml-explore/mlx/blob/v0.32.2/mlx/backend/metal/scaled_dot_product_attention.cpp#L619)
  是依据；调用 `fast` API 本身不是已融合或已提速的证明。

当前候选将注意力内部的 Q/K/V 从 32 维补零到 64 维，以符合现有融合核的
布局要求。仍按 32 维缩放，输出裁回 32 维；权重不变，KV 缓存容量翻倍。
每步只给新增行补零，避免重新复制整个历史。先做小规模数值检查，速度取舍
留到最后的 Mac 实测。

该候选的 10 项定向测试通过，覆盖源实现对齐、补零前后计算、缓存扩容及
未使用缓存污染。真实权重另做一次 prefill 加 4 步 decode：FP32、FP16
各 5/5 次 top-1 与 Torch 一致，输出均有限；最大 logit 误差分别约为
3.15e-5、0.0814。FP32 通过原有 1e-4 容差，FP16 仅记录误差与排名，
不据此宣称音质通过或 Metal 加速成立。

## 当前版本的本机速度对比

2026-09-30，在干净候选 `bf31a2c` 上补做 Windows 11 / Ryzen 9 8945HS
CPU 快速对比：Python 3.12.10、Torch 2.7.0+cpu、MLX/MLX CPU 0.32.2，
线程设置为 4。同一真实前端 fixture（104 个音素、191 个参考语义 token），
固定 32 步解码，包含每步采样、EOS 主机读取和末尾计算完成。
五个变体各用独立进程，先正序再反序；每个进程预热 1 次、测量 5 次，
每个变体合计 10 次。模型加载不计时。此处没有声学合成、播放或音质测量。

| 变体 | prefill p50（ms） | 32 步解码 p50（ms） | 两阶段总计 p50（ms） | 总计范围（ms） |
|---|---:|---:|---:|---:|
| Torch FP32 | 200.1 | 791.6 | 988.7 | 978.9–1023.7 |
| 审计原版 MLX FP32 `a1873b7` | 674.6 | 940.6 | 1611.7 | 1502.9–1919.5 |
| 补零前 MLX FP32 `184543d` | 773.5 | 1080.7 | 1868.6 | 1791.3–1998.4 |
| 当前 MLX FP32 `bf31a2c` | 773.8 | 1089.3 | 1861.0 | 1715.3–2001.4 |
| 当前 MLX FP16 `bf31a2c` | 11029.3 | 4483.7 | 15513.4 | 15432.2–15831.2 |

总计取每次两阶段之和的中位数，不是两列中位数相加。样本量仅用于短检查，
不据此估计稳定的 p95。当前 FP32 在本机比 Torch 的两阶段总计慢约 88%，
比审计原版 MLX 慢约 15%；与补零前版本接近。FP16 CPU 路径明显更慢。
这轮没有证明本机加速，也没有复现此前一次“优化后 CPU 不退化”的方向，
因此不能把历史那次结果当成稳定结论。源 FP16 参数数组较小不等于 CPU
执行更快；Metal 上的取舍仍须实测。

本地原始每轮及每步数据保存在
`output/diagnostics/mlx-audit-followup/cpu-bf31a2c/`，运行脚本为同级的
`compare_current_cpu.private.py`。fixture SHA-256 为
`a45014f13ae9481f439855aaa4426fcb0c1bcdc788122169cbc31e58406c1223`。
实现可以交给 Mac 做首轮实验；完成速度和音质验收前保持实验状态。

## 实现与验证原则

产品只保留一套优化 MLX 实现。dtype 是 decoder/探针参数，产品暂用 FP32，
不新增用户配置开关。旧实现仅用于固定提交的诊断对照，旧同步循环仅用于测试。
首句音频缓存供两种后端共享；所有 A/B 测试统一关闭完整音频缓存。

FP16 仅用于模型计算；采样前转 FP32，保持重复惩罚、top-k 并列值、EOS
和预算语义。前瞻只计算下一步 forward，不多消耗采样随机数。
测试需要同时检查输出 token、idx、停止边界及后续 RNG 状态。

Windows 的结构探针 `tools/probes/gsv_mlx_structure.py` 从固定审计提交
`a1873b7` 读取旧模型，并与当前实现使用相同输入：

| 指标 | 能证明什么 | 不能据此声称什么 |
|---|---|---|
| DOT primitive 节点数及分布 | 当前 CPU 图中实际保留的运算节点 | Metal 内核数量 |
| Python 建图时间 | 同步诊断条件下构建一个 forward 的耗时 | 建图已被 GPU 计算完全覆盖 |
| KV 新 token / concatenate 数组字节数 | 更新规模及扩容位置 | Metal 实际拷贝为 O(1) |
| 权重数组字节数 | FP16 参数驻留大小减半 | 带宽流量减半或速度翻倍 |

`slice_update` 能否原地写取决于缓冲区捐赠；实际复制和前瞻重叠需要 Mac
设备分析。CPU 下 `fast` API 也可能分解，因此“图节点减半”必须报告是否
达到，不能拿估计的高层算子数量替换实测 DOT 数量。

## Mac 比较对象与判定

四个 T2S 变体分别测量：Torch FP32、Torch FP16、MLX FP32、MLX FP16。
Torch FP16 只改变探针内的语义模型，声学链精度保持相同。每种独立进程、
交替执行、至少 20 次，保留每次和每个 token 位置的原始计时。
固定历史比较计算成本，自由生成和真实音频检查产品行为，两者不混为同一指标。

先对 Torch MPS 生产基线做首句、中句、长句的阶段拆分，再测自然执行的首块
时延。诊断同步会改变调度，因此阶段剖析与自然端到端测量分开；不能把重叠
计时相加当成用户时延。冷启动与预热后的结果分开报告。

交接文档建议的决策门槛如下，作为报告标准，不自动批准采用或放弃某个后端：

- 若 T2S 占首句首块时延不到 25%，优先评估声学链的优化空间。
- 若 Torch FP16 获得了最佳 MLX 相对 Torch FP32 所节省 T2S 时间的至少
  80%，优先审查改动更小的 Torch FP16 方案。
- MLX 候选需 T2S p50 至少快 2 倍、首块 p50 降低至少 15%、p95 不变差，
  并通过持续请求内存检查和音质检查。
- ASR 是可懂度预筛，不能代替人耳对音色、韵律、噪声和截断的判断。
  Windows FP16 样本预筛不能取代 Mac 输出的再次听测。

Linux 数值通道、Windows dry-run、Mac 实测和真人听测分别记录实际完成状态。
没有执行的项目保持未验证，不能因脚本存在或其他平台通过而标绿。

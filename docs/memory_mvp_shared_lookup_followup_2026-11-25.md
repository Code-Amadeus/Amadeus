# 显式回忆的会话出处与一次补查

基于 `375e14f` 的正常 Chat 查阅流程。桌面按钮和角色主动查阅共用相同的出处证明、补查动作和最终读集。沿用 schema 19 与默认关闭的来源开关。

## 来源与补查

Host 在首包中可附上同一会话、同一世代的来源短号和位置间隔。相隔两个位置时，中间位置必须仍可读，且把该版本登记到读集。记录顺序来自首次提交，当前会话也必须仍有对应位置。捕获暂停期间写下的中间句、不可读记录和撤回的位置会阻断证明。位置只说明原会话先后，承接和转题由读到的原话决定。

角色对现有材料已经能说清的部分可直接作答。仍缺一条原话时，可在已有回复末尾提出一个明确缺项的语义查询，或用已显示的来源短号查前一条或后一条用户发言。位置补查最多跨过一条仍获准的助手发言。Host 只在原作用域中执行；没有可新增的完整依据时沿用已核准的首稿。新增完整依据后才生成末稿，末稿不再获得补查能力。

首包和末包分别按最多八组、1,024 计量 tokens、8,192 字节核算。附位置证明放不下时保留正文。新依据放不下时，只能按角色显式指定让出一组与其他组独立且不作为锚点的原话。已经被角色读取的版本和位置依赖继续留在最终读集，即使相应正文已经从末包移除。

## 本机验收

通过正常 `chat.send` 接通实际 Session、Host、Eidema 和发布入口。固定角色回执覆盖相同首包下的真承接与转题、不可读中间位置、暂停记录导致的位置缺口、满八组的让位与保留、读完位置证明后撤回、越权参数和隐藏短号，以及重复提出补查。承接和转题分别得到各自的真实原话。找不到额外依据的用例复用第一稿，最终答案没有提前进入显示或朗读。

内部 **19/24、零严重误用**仍为历史质量参照，桌面 A **18/24**为同入口对照。这次证明真实入口具备交付能力。下一次实答需核查角色能否自主提出合法补查、能否用对承接或保留未知。内部和已见公开题分开做同题对照并报告逐题得失。45 道公开留出仍用于冻结后的泛化验证。

# 正常 Chat 的跨会话显式查阅

在来源投递提交 `b297de9` 上接入共享的显式查阅。桌面按钮沿用已受理的问题。自然对话由角色使用已有的 `memory_lookup` 操作提出只读查阅。两个入口在同一个 Host 流程整理材料、登记读集和发布答复。开关仍默认关闭。

| 边界 | 当前契约 |
| --- | --- |
| 检索 | 来源与保存笔记共用一次查询嵌入。复用两路原生余弦，相似度缺失时保留各自的词法顺序。角色提出查询，账户、角色和项目范围由 Host 决定。 |
| 入模 | Eidema 装配完整依据组，上限为八组、1,024 计量 tokens、8,192 字节。优先交付具备当前版本与查阅许可的原话及已保存的笔记。当前问题以已受理的消息身份去重，提问时钟来自其 Session 记录。 |
| 撤回 | 重新读取使用中的 Session，复核实际入模原话及派生材料的上游来源。索引落后一拍时，旧候选可从首包中省去。生成过程中被撤回的已用依据会阻止旧稿进入显示和朗读。 |
| 持久性 | 只登记实际交付的笔记版本、原话版本及已有历史依赖。已发布查阅答复保留在用户会话。其原话仍有效时，新显式查阅可以在原权限内复用。普通角色历史继续按用途过滤，并保留独立可用的旧笔记答复。 |

本机固定回执经正常 `chat.send`、Session 持久化、Host 与锁定的 Eidema wheel 验证。按钮一次回答，主动查阅为既有的一次决策和一次查后回答。普通聊天对照只有原角色调用，未检索原话。正向用例把当轮问题实际加入索引后才开始选材，最终包和读集仍只保留其他依据。四种故障时机覆盖删除或修订发生在组装前与发布前，并用仍包含旧内容的实际索引作阳性对照。另验证原话失效能传到其派生答复，独立内容可继续交付。合成中日向量测试验证了两路复用一次编码。

该版本进入了可复用的本机查阅链路。实际自主补查、来源承接关系、内部和公开实答以及真人声画验收仍按 MVP 发布标准进行。历史 19/24 与桌面 A 18/24 各自保留原测量含义。

# Eidema 第二批重构验收

第一批的 Amadeus 基线是 `f39b53df`，内置 Eidema `0.2.0a2`。本批内置
Eidema `0.2.0a3`（`d23e1efe`），应用仍以 Amadeus 0.18 Alpha 1 为发布候选。

## 复审范围

| 边界 | 本批交付 |
| --- | --- |
| 来源与形成 | Amadeus 的 Session 适配器提供规范原话、权限与版本校验。SDK 在派发、提交和自动采用前使用同一公开守卫。已发请求的用量结算与候选发布各有自己的权限检查。 |
| 维护重启 | SQLite schema 20 将调度检查点纳入 Eidema 主库。旧维护文件只读导入一次，保留温冷通道顺序、轮询游标、时钟和后处理进度。旧文件保留，来源政策文件继续由 Host 管理。 |
| 语音撤回 | Host 显式通知语音注册器。合成管线使用正式的挂载接口。更正、遗忘或退役使对应待播片段失效。跳过失效片段时会归还合成并发许可。 |
| 查阅 | Eidema 的 `LookupEngine` 负责两路召回、证据预算、邻接补查和摘录选择的读集登记。Amadeus 提供 Session、角色提示和模型调度。 |
| 离线嵌入 | `eidema[onnx]` 可使用本机 CPU 加载已有的 ONNX 图。Amadeus 继续固定 Jina 权重、许可证和运行库版本。 |

## 回归证据

- 24 个固定回执场景和 Alpha.2 逐项一致。包括 33 份模型适配器调用、20 份输出读集、
  24 份显示文本和 24 份语音队列文本。
- 已安装 Alpha.2 和 Alpha.3 轮流打开同一套合成库。schema 19 升级到 20 后，笔记、索引、
  已结算用量、来源游标和温冷检查点均可复核。旧维护文件哈希保持一致。
- 已安装的同一份 Jina Q4 权重通过新旧实现核对。5 个查询和 30 个片段向量逐值一致。
- 语音回归覆盖更正、遗忘和删会话，各自验证待播语音被跳过且独立语音仍可合成。
  Electron 全量测试 789 项通过，生产构建通过。

回归使用合成数据和固定回执。真实设备首音延迟与生成质量仍以各自的专项实测为准。
桌面保留已有的两个记忆开关。冷生成在 Alpha 默认暂停，已绑定的冷通道仍可恢复。

## 数据升级

升级前请保留一致的本地数据备份，包含 Session、Eidema 主库、来源政策文件以及已有的
旧维护文件。回退到 schema 19 的 SDK 时，需要恢复对应的升级前备份。

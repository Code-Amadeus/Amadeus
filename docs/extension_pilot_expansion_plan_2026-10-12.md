## 1. 现有统一模型

只有一种包清单、一套 Electron 安装/记录事务和一个 Plugins 管理入口；Settings 复用它。
支持矩阵 `server/extensions/profile.json` 与生成的 Electron 副本控制可接入类型；各原生 owner 保留运行和权限责任。

| 类型 | 当前状态 | 接入与生效 |
|---|---|---|
| TTS | 已实现 | 选择语音；保存后重启 |
| MCP | 已实现 | 绑定兼容 Work Provider；保存后重启 |
| Skill | 已实现 | 安装一次、选择 Agent；保存后重启 |
| 主题 | 已实现 | 纯前端即时；混合包整包随后端重启 |
| surface / ASR / 可安装 AUIP | 关闭 | P3/P4/P5 候选，尚无当前 Host 准入 |
| context_source / observer / 角色或形象包 | 关闭 | 分别等待记忆或形象契约，不由此表自动开放 |

安装不授予 Main Chat 执行权。现阶段 `permissions.host` 必须为空，无 Grant 记录；OS 声明不等于 OS 沙箱。
“保存”“明确接受/拒绝”“没有有效回执”“实际健康”“文件已清理”是不同事实。
混合包停用/卸载先关闭前端，旧后端可仍待停止；只有真实引用和确认退出允许清理。

## 5. P3：扩展窗口（未实施候选）

### 5.1 扩展窗口（唯一新增的 owner）

**结构：** 与 Work Preview 相同，由 Host 外壳页面加一个沙箱内容视图组成。内容视图的配置参照 `openAuipInWorkPreview`（`electron/src/main/index.ts:2051`）：

- `sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`、`webSecurity: true`；
- 分区为 `persist:amadeus-ext-<sha256(packageId) 前 16 位>`。同一个包的所有窗口共享这个分区，不同包之间隔离。

**规则按 Session 统一管理：**

- Electron 的 `webRequest` 对每个事件只使用最后注册的那个监听器，而 `restrictAuipContentNetwork`（`index.ts:1882`）每次调用都会注册一个新监听器。因此不能每开一个窗口就注册一次。
- 改为在分区首次创建时，按 Session 安装一次监听器，查询该包统一的策略对象。
- 窗口级的状态（例如文件查看器当前打开的是哪个文件）放在通信桥里，不放进 webRequest。
- `setPermissionRequestHandler` 和 `setPermissionCheckHandler` 都设置为一律拒绝，设备和屏幕采集的处理器也同样拒绝。

**稳定的 origin：**

- `amadeus-ext` 协议的主机名取包 id 的稳定哈希，不取安装 id。这样更新后 origin 不变，保留的网页数据仍能访问。
- 重新安装同一 id 的包会沿用同一个 origin。卸载时选择删除数据，则清空该分区的存储。

**资源协议：**

- scheme 的 standard/secure/supportFetchAPI 属性在 app ready 前一次注册；资源 handler 只挂在对应扩展 Session，主窗口 Session 不提供扩展文件。
- 同包稳定 origin 下，用贡献 id 对应的路径前缀映射已声明 root，复用 `assertExtensionPath` 的无链接检查；只从实际加载版本提供资源。同包共享 origin/storage 是明确的信任范围，不宣称同包各网页相互隔离；不同包不能读取对方资源。
- MIME 白名单：html、js、mjs、css、json、png、jpg、webp、svg、woff2、wasm。
- 每个响应附带 CSP：`default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; connect-src 'self' <声明主机>; object-src 'none'; frame-ancestors 'none'`。

**守卫与网络：**

- 导航守卫沿用 `guardAuipEntryNavigation`（`index.ts:1888`）的做法，只允许包内导航；拒绝打开新窗口、webview 和下载。
- 网络默认只允许访问本包的协议地址；`permissions.os.network` 中列出的 `https://` 主机放行。网页层的网络限制由 Electron 真正执行，界面上写"已限制"；Runner 的网络披露仍写"未强制"。

**外壳与窗口规则：**

- 外壳显示扩展名、版本、"扩展内容，非 Amadeus"标记和关闭按钮，扩展无法修改外壳。
- 主窗口获得焦点时，扩展窗口取消置顶；主窗口失焦后仅为用户原本选择置顶的小组件恢复。来源栏不能进入扩展的可绘制区域。

### 5.2 通信桥

- 内容视图只加载一个最小 preload：`electron/src/preload/extension.cts`。它只暴露 `amadeusExtension.request(method, params)` 和 `amadeusExtension.on(event, handler)`。
- 不暴露 `window.amadeus`，页面也拿不到后端连接凭据。
- main 校验已登记的 sender、主 frame/origin 与仍有效的加载修订，确定包、贡献和呈现方式；不信任参数自称身份，不接收其他 frame 冒用。关闭、导航失效、停用、更新切换后撤销旧视图的桥身份。
- 报文格式和错误码沿用 Runner 协议（`-32601`、`-32602`、`-32001 capability_denied`）。

| 方法 | 可用于 | 结果 |
|---|---|---|
| `host.context.get` | 全部 | locale、主题 token 值、`colorScheme`、包 id 和版本、呈现方式 |
| `host.config.get` | 全部 | 本视图实际加载快照的非密钥配置，不能把新期望配置注入旧版本页面 |
| `host.config.update` | settings | 经同一校验器写期望记录，沿用 §1 的整包生效边界。不能读写密钥。若视图加载修订已不同于期望修订，则拒绝旧页保存并引导回 Host 管理页，避免旧 schema 覆盖新配置。 |
| `viewer.document.get` | file_viewer | 当前文件：`{title, suffix, sizeBytes, sha256, content}` |
| 通知 `host.context.changed` | 全部 | 主题或语言变化 |

本阶段不提供：后端调用、Main Chat、Work、让角色发言、读取其他包或其他文件、与本包 Runner 通信。

### 5.3 三批呈现方式

```json
"contributes": { "surface": [
  { "id": "pomodoro", "contract": "amadeus.ui.surface/v0", "presentation": "page",
    "root": "ui", "entry": "index.html", "title": { "zh-CN": "番茄钟" } },
  { "id": "csv-table", "contract": "amadeus.ui.surface/v0", "presentation": "file_viewer",
    "root": "viewer", "entry": "index.html", "file_types": [".csv", ".tsv"] }
]}
```

- **P3a：扩展窗口、通信桥、页面（page）。** 在 P2 已有的“插件”管理页增加打开入口；5.6 的共同安全与页面验收在本批完成，其他呈现专属验收随 P3b/P3c。
- **P3b：设置页（settings）与文件查看器（file_viewer），依赖 #189。**
  - settings：管理页里每个包上有"打开扩展设置"，只能读写本包的配置。
  - file_viewer：`file_types` 只能是 `TEXT_SUFFIXES`（#189 的 `server/work_artifact_source.py:12`）的子集。`WorkFilesPanel.tsx:67` 的预览区提供"用 <查看器> 打开"。Host 沿用已登记版本的校验路径读出内容，再交给查看器；查看器拿不到文件路径，也接触不到 Work 账本。同一文件类型有多个查看器时，由用户选择并记住默认值。
- **P3c：小组件（widget）。**
  - 紧凑型扩展窗口，Host 限定尺寸（例如不超过 360×240），位置由用户拖放。
  - 允许置顶，但受 5.1 的焦点规则约束。
  - 每个包最多一个；失去焦点时节流。
- **资源上限：** 同时存在的扩展内容视图数量设上限（例如 4 个），超过时提示用户关闭。每个视图的内存占用显示在管理页上。

### 5.4 "插件"管理页（统一入口）

- P2 在主导航新增"插件"入口。它是所有已安装类型的管理页，提供：运行状态、待生效变化、启用/停用、配置与凭据、Agent 绑定、更新、卸载与数据保留；P3/P5 只逐步增加对应“打开”动作。
- 页面和 AUIP 应用只是管理页里可以打开的内容。
- 设置 → Extensions 导向同一管理视图或复用同一个组件与数据源，不创建第二份草稿/生命周期状态。Voice、外观、Agent 页只负责选择或使用能力，并链接定位到所属插件。
- 插件卡片区分“已保存”“当前加载”“健康状态”“待停止/删除失败”，支持按类型/状态筛选；更新/移除仍从卡片进入。没有 page 贡献的 TTS/MCP/Skill/主题包也必须可见、可管理。
- 入口与桥分开：Host 的凭据编辑只在可信管理组件，扩展自己的 settings 页面不能代替它或取得密钥。

### 5.5 生命周期与版本释放

整包版本切换适用于主题、surface、TTS/ASR、MCP/Skill 和以后 AUIP 的组合。**先证明旧 owner 已释放，再清理旧资源；保存期望状态不是释放证明。**

| 操作 | 只含前端贡献的包 | 旧/新版本任一包含后端贡献的包 |
|---|---|---|
| 首次安装 | 默认停用；确认启用后才能选择/打开 | 默认停用；启用保存为待重启，重启应用前不开放网页/主题/后端贡献 |
| 配置/更新准备失败或用户取消 | 期望记录、活动版本、存储保持原样 | 同左，运行中的旧后端不受影响 |
| 更新/配置提交成功 | 关闭旧视图并撤销桥，切换同包资源/配置，释放旧引用后清理；不自动重开窗口 | 保存期望 v2/r2；旧窗口、后端、新打开的允许入口仍使用活动 v1/r1，不混读新配置或网络披露；管理页明示待重启 |
| 停用/请求卸载 | 阻止新打开、关闭窗口、主题回退；释放引用后完成清理 | 立即执行相同前端收口；后端 v1 到重启才停止，显示“前端已停用，后端待重启” |
| 再次启用 | 确认后应用当前有效记录 | 确认后保存为待重启；不重开仍待停止的旧版本网页 |
| 重启与换版 | 不要求重启后端 | 先关闭旧视图、撤销旧桥并确认旧后端及其受管资源停止；再启动/注册新快照，由对应 owner 确认实际应用后开放该版本的前端入口 |
| 回收旧安装目录 | 所有视图/协议读取/主题资源引用释放后 | 上述前端引用已释放，且 Runner、MCP 与使用包资源的受管 Agent 会话已终止或明确释放引用后 |
| 卸载保留数据 | 保留包数据和网页分区，清理安装文件及配置/凭据记录 | 等后端停用与引用释放后完成卸载，保留相同数据；不把等待当成已卸载 |
| 卸载删除数据 | 关闭所有视图及相关执行上下文后清空分区、缓存与包数据，无需无关后端重启 | 确认该包的前后端 owner 都已退出后，清空分区、缓存与包数据 |

- **停止/清理失败：** 不删除仍可能被使用的目录或数据，不提前销毁所有权标记，保留 pendingRemoval/错误供重试；不能通过改路径、降权限隔离或强制覆盖解决。
- **提交后的激活失败：** 与“准备失败”分开报告。保留已提交期望记录和错误，不能报告新版本已运行；新后端未接受快照时混合包前端入口保持关闭。已停止的旧后端不自动复活，也不自动降级版本；修正配置或显式重新安装后重试。
- **包种类改变：** 后端包更新成纯前端包也要先按重启释放旧后端；纯前端包更新成混合包也不能提前开放新网页。类型变化不能绕过同一次安装事务。
- **保留数据重装：** origin 与包数据身份按包 id 保持；包默认停用，移除的配置、凭据和 Agent 绑定不自动恢复。包自行负责其保留数据格式兼容，Host 不执行隐式数据迁移脚本。
- **进程重启恢复：** Electron/后端重启后从期望记录和实际启动结果重建状态；没有运行进程时不得沿用上次的“运行中”标记。正常启动、启动失败及未完成删除均要覆盖。

### 5.6 验收

- **安全（每条都要有自动化测试）：**
  - 页面中看不到 `window.amadeus` 和后端凭据。
  - 不同包的存储相互隔离。
  - 同一个包打开两个窗口时，网络策略不会相互覆盖。
  - 对未声明主机的 fetch 和 WebSocket 被拒绝。
  - 导航到包外、打开新窗口、下载被拒绝；权限请求与权限查询都被拒绝。
  - `file://` 不可读。
  - 错包/子 frame/已关闭或旧修订的视图不能使用桥；旧 settings 页面不能覆盖新期望配置。
- **数据和版本（P3a）：** 同包不同窗口共享存储、不同包隔离；v1→v2 后 origin 不变；纯网页包与网页+TTS 混合包分别执行 5.5 矩阵。覆盖更新前后新开窗口、Electron 退出重开、后端启动失败、卸载清理失败重试、保留/删除数据后重装，不能只测资源复制。
- **呈现：**
  - 外壳始终显示来源。
  - 主窗口获得焦点时，扩展窗口不在其上方。
- **设置与文件查看器（P3b，基于 #189）：**
  - 配置只写本包已声明的非密钥字段；普通页面不能调用 settings 专属方法，密钥字段不能读写。
  - 只收到被打开文件的当前登记版本。
  - 文件被改动后拒绝打开，并提示刷新。
  - 明确打开文件/查看器即仅同意交付这一已登记版本；有网络声明时在 Host 选择处展示。对内容和默认查看器选择做更新/卸载回归，不向扩展传递路径、账本或任意文件读取方法。
  - 回归普通文件/AUIP 混合交付：报告仍归文件，查看器打开不构成 AUIP Attach，也不接受 WorkItem。
- **小组件（P3c）：** 用户选择置顶→Host 得焦→取消置顶→Host 失焦→恢复用户偏好；未选置顶的不提升。测试尺寸上限、位置恢复、每包数量限制、禁用/卸载和节流。
- **性能：** 达到内容视图上限后明确拒绝额外打开；冷启动基线之后打开/关闭 20 次，受管视图与活动任务归零，区分 Chromium 可复用闲置进程和孤儿执行；记录内存是否持续增长及测量口径。
- **示例包（全部本地运行，不联网）：** 番茄钟页面、CSV 表格查看器、桌面时钟小组件。
- **实机证据：** 每批使用构建后的 Electron 操作完整路径，附截图/短记录和确切命令；安全边界自动化、界面 smoke 与人工/真实进程验收分开报告。有关 API 约束参见 [Electron WebRequest](https://www.electronjs.org/docs/latest/api/web-request)、[Session 权限处理](https://www.electronjs.org/docs/latest/api/session)、[IPC sender 校验](https://www.electronjs.org/docs/latest/tutorial/security#17-validate-the-sender-of-all-ipc-messages)。

## 6. P4：ASR（先只做最终识别，再接投机识别）

### 6.1 P4a：只做最终识别

- **Host 侧：**
  - 在 `ExtensionRuntime.start` 中用 `register_asr_backend`（`asr/registry.py:51`）注册 `ExtensionASRBackend(BaseASRBackend)`。
  - `supports_speculative_transcription` 固定为 False。
  - 沿用现有接口 `transcribe(audio, sample_rate, context)`（`asr/backend.py:43`）。
- **Runner 侧：**
  - P4a 才扩展 Host 注册/健康检查和 SDK 方法分派，支持 `voice_backend/asr`；仍按声明精确核对注册 ID，不为 future 类型创建通用动态执行入口。
  - 一次识别是一个带截止时间的请求。
  - 沿用 voice-v0 的 `segment_id`（本阶段用于单次请求关联）、`mode=final`、16000 Hz 单声道 PCM16/base64、最长 120 秒、hotwords 与 deadline。Host 在现有 float32 接口和 wire 间转换；不向旧接口虚构 speculative 身份。
  - 超时后发送 `$/cancel`。只有收到终态/取消确认，或确认执行进程退出，才释放并发名额；Host 丢弃迟到结果或移除等待者不是释放证明。容量满时快速返回可见不可用，不重试付费识别。
  - 这套请求生命周期与 TTS 共用，在 Runner 客户端中统一实现。
- **选择：**
  - 到 P4a 才为 `ASR_BACKEND` 接入 #191 已有的贡献选择校验，接受完整 id；沿用内置 ASR 选择原有的 `apply: host`，新增扩展包的生效边界另按本节验证。
  - `WAKE_ASR_BACKEND`（`config/catalog/voice/wake_asr.json`）不接受扩展。
- **隐私：** 远程 ASR 在选择处标明"麦克风音频会离开本机"。只有被选中的后端会收到音频。
- **失败：** 沿用现有的 ASR 失败路径（提示并允许打字），不自动换用其他远程后端。
- **SDK：** 提供 `@extension.asr("id")`，同步函数返回 `str | None`。
- **验收：**
  - 最终识别、取消、超时、Runner 崩溃、重启恢复各有测试。
  - 同包 TTS+ASR 的注册、共享容量与故障范围；连续慢取消不耗尽崩溃预算，迟到文本不成为新的用户输入。
  - 错误采样率、超时长、非法音频、空结果；选择变更发生在录音/识别期间时不串后端、不重复交付同一段结果。
  - 无扩展时内置后端选择、wake、回退行为不变；新增 ASR 安装需重启，已注册后端的选择沿用原有即时语义。
  - 打断（barge-in）和回声防护不受影响。
  - 确定性合成音频覆盖协议；真实麦克风用同一组约 5 秒语音对比内置与扩展的端到端延迟，并验证打断、恢复、空音频与键盘可用。分别记录本地/远程服务、硬件与测试范围；没有 key 时把远程验收列待办，不能以 mock 冒充完成。

### 6.2 P4b：投机识别（同一阶段，分开验收）

- 当前 ASR 接口没有 segment 身份和识别模式；投机识别作废时，只是把结果丢弃。接入投机识别需要：
  - 在 Host 的 ASR 接口中引入 segment 身份和模式（final/speculative）；
  - segment 身份由 capture/manager 创建并沿同一段的调用传播；不由插件按音频长度或文本猜测。内置调用保持原有端点/复用语义。
  - 同一 segment 的最终识别到来时，取消尚未完成的投机请求；并发名额仍按 P4a 的终态规则释放，不能在发送 cancel 时提前释放。明确 final 的有界准入与过载反馈，不用无限排队掩盖慢取消。
- 清单通过 `speculative: true` 声明支持。没有声明的后端继续只走最终识别。
- **验收重点：** 内置后端的语音端点判断行为不变。扩展后端的投机结果只作为提示，只有最终结果会成为用户的这一轮输入。
- **退出证据：** 覆盖暂停后继续说话、跨 segment 迟到、投机已完成/仍在运行/失败、final 与取消竞态、打断后重新录音；每段最多一次最终交付，无旧投机文本串入。实机比较 final-only 与 speculative 的延迟及识别结果，同时通过内置语音基线回归。

## 9. 插件商店与热重载（后续阶段）

候选目标：用户在"插件"管理页（5.4）中浏览、下载、安装、更新插件，部分插件支持热重载。以下是立项后才评审的候选设计，不是当前管理器已提供的能力。

### 9.1 商店：只做索引，不托管安装包

- **索引仓库。** 一个公开的 git 仓库或目录，每个包一个 JSON 条目，包含：
  - 包 id、展示信息、维护者；
  - 每个版本的产物地址（GitHub Release 或 PyPI）、sha256、清单摘要、最低 Host API、支持的平台；
  - 等级：community 或 verified。
- **收录流程。** 作者提交 PR，CI 执行检查：
  - 与 Host 相同的清单和包检查；
  - 下载产物并核对 sha256；
  - 拒绝 `.pth`、源码包和超出限制的包；
  - `io.github.<owner>.*` 命名空间必须与 PR 作者的 GitHub 账号一致。

  verified 等级另需维护者人工审查。等级只影响提示的强度，不影响任何权限。
- **撤回。** 索引包含已撤回的版本和封禁列表。已安装的版本若被封禁，下次启动时不激活并显示原因；数据保留，不静默删除。
- **信任前提。** sha256 只有来自可信索引时，才能用来校验镜像提供的包；如果镜像同时提供可被替换的索引和 wheel，攻击者可以同时修改两者。因此：
  - 索引只从官方来源经 HTTPS 获取，或者使用签名索引，由 Host 内置的公钥校验签名；
  - 镜像只用于下载产物，产物按可信索引中的 sha256 校验；
  - 如果镜像也要提供索引，那份索引必须带签名。
- **客户端。**
  - 只在用户打开管理页的商店视图时拉取索引，没有后台上报，也不统计。
  - 下载完成后，走与本地 wheel 完全相同的安装事务和确认页，确认页显示等级与来源。
  - 离线时仍可安装本地 wheel。
- **S1 引入的管理字段：**
  - 记录的来源（本地文件或索引）与等级（local、community、verified）；
  - 安装入口接受索引给出的预期 sha256，不符即拒绝。
- **更新。** 有新版本时提示"有更新"，由用户点击更新，不做自动更新。确认页沿用 Plugins 现有边界，突出显示新增的披露与贡献。
- **依赖。** 仍然只安装 wheel。条目展示依赖的下载体积。需要 CUDA 版 torch 这类重型 GPU 依赖的包，不进入商店的第一阶段。

### 9.2 热重载：按 owner 分级，不回到"整条管线热切换"

| 类型 | 目标生效方式 | 机制 | 阶段 |
|---|---|---|---|
| theme（只含前端类型的包） | 即时 | 前端 owner 重新渲染 | 已实现；文件监视热重载未实现 |
| surface（只含前端类型的包） | 即时 | 前端 owner 重建视图 | P3 候选，未实现 |
| auip_app | 即时 | 协调后刷新包应用来源；已打开的会话不受影响 | H1 |
| TTS、ASR | Runner 换代 | 稳定代理内部先启动新一代 Runner，就绪后新请求转到新一代，旧一代在有界时间内结束；TTS 管线和 ASR manager 都不感知 | H2 |
| mcp_server、skill | 新会话生效 | 协调后更新进程内的 MCP/Skill 注册表；已有会话按 Skill 修订规则继续或被拒绝 | H3 |
| 内置设置的选择（`TTS_BACKEND` 等） | 不变 | 沿用各自原有的生效语义 | — |

- **通道（H1 引入）：**
  - Electron main 通过一个已鉴权的后端方法 `extensions.reconcile { records }` 推送期望状态。格式与启动快照相同，经过同一套校验。
  - Python 逐包比较期望与实际状态，操作幂等，并回报每个包实际生效的 revision。
  - 启动流程同时改为一次协调。
- **包版本：** 当前混合包仍按 §1 的规则整包随重启切换。H1/H2 若允许旧一代已准入请求收尾，则需要单独定义“当前接受新请求的版本”和“仍持有资源的旧一代”，不能沿用“只有一个 revision 就可删除旧目录”的推断；网页切换、引用释放与数据兼容在热重载阶段重新验收。
- **安全规则（与协议 §4.4 一致）：**
  - 新一代启动失败时，只要旧一代仍被允许，就由旧一代继续服务。
  - 停用、卸载、清除必需密钥会立即关闭准入，不依赖旧一代。
  - 已经失败的请求不重放。

### 9.3 开发者模式

- 贡献者可以把源码目录"链接"为本地包：等级为 local，永远不会自动启用。
- 网页类型的文件变化时自动刷新视图；Runner 类型的文件变化时触发换代（H2 之后）。
- 从商店安装的包不受文件监视。

## 10. 形象包（后续阶段，第一批不做）

目标：社区用 SpriteForge 制作的角色素材（或 Live2D 模型）作为扩展安装，在外观页全局选择。

它与人格、记忆无关：形象配置由整个应用共享，不使用 `character_id`（`docs/live2d_character_visuals.md`）。以后人格配置只需引用形象配置的 `profile_id`，就能做到每个角色各用自己的形象。

### 10.1 现状（2026-10-12 核对 Amadeus main 与 SpriteForge main `ce25816`）

- **SpriteForge 导出的包里已经有：**
  - 全部动画片段与贴图；
  - 行为图：节点、自动跳转的权重，以及只能由意图触发的手动边（`prob: 0`）；
  - 嘴型配置。凡绑定了嘴型的循环片段都会导出嘴型配置与覆盖层，所以包里已经标明哪些节点是说话循环（SpriteForge `src/spriteforge/production/exports.py:176-183`）。

  因此任何包装进来，待机遍历和说话循环上的口型同步都能工作。
- **包里没有语义绑定。** Amadeus 遇到开始说话、认真说话、思考、要点强调、各情绪的进入/说话/停留、说完释放这些事件时，进入哪个节点是按 Kurisu 包的节点名写死的：
  - `render/spriteforge_animator.py:42-107` 和 `render/spriteforge_intent.py:19-35`；
  - 网页渲染器读取 Python 下发的配置，默认值也是这些名字（`render/web/renderer.js:1033-1035`）；
  - 另有两条按 Kurisu 美术调过的嘴型遮罩参数，写在 `spriteforge_animator.py:123`。

  SpriteForge 那边也是这样划分的：`behavior.py` 开头写明它不实现语义别名、说话停留和说完后的释放；`docs/character_pack_authoring.md` 写明这些仍是 Amadeus 的运行时配置。
- **加载位置固定。** 只从 Kurisu 的目录加载（`config/asset_paths.py:19`）；形象配置只支持 Live2D（`render/visual_profile.py:60`）。
- **小结：**
  - 节点名照抄 Kurisu 的包，现在已经能说话、能做情绪；
  - 自己命名节点的包，只有待机和口型；
  - 两种包都只有放进固定目录才会被加载。

### 10.2 方案（按顺序）

1. **包内语义绑定。** 这一步要改 SpriteForge 契约，工程量主要在这里。
   - character-pack 增加一份语义绑定文件，由新版本 runtime manifest 的字段引用。v1 manifest 是 `additionalProperties: false`，不能直接加字段；也不做按文件名猜测的探测。
   - 绑定声明以下内容：开始说话的入口（含权重和闭眼变体）；说话循环的类别（普通、认真、思考、要点）；各情绪的进入、说话、停留节点；说完后的释放。
   - 语义词汇与 Live2D 的 `emotion_map`、`render.character_intent` 使用同一套。
   - SpriteForge Studio 给节点增加语义标签，导出时写入并校验。
2. **迁移 Kurisu。**
   - Kurisu 包导出一份与现有常量完全等价的绑定。
   - `spriteforge_animator.py:123` 的两条嘴型参数移入 Kurisu 包的嘴型配置。
   - 验收：Kurisu 的事件、配置值、随机选择次数与改动前逐字节一致（角色身份方案对表现抽取的要求）。
3. **Amadeus 读取绑定。**
   - animator 和 intent 模块改为从包读取绑定，删除硬编码常量。
   - 没有绑定的 v1 包按"只有待机与口型"运行，外观页显示该包的能力说明。
4. **Sprite 成为可选的形象配置。**
   - `VisualProfileStore` 增加 `kind: "sprite"`，指向包目录，外观页可以选择。
   - Companion 和 VN 继续使用 Kurisu 素材，直到各自有实机验证。
5. **扩展类型 `visual_pack`（数据层）。**
   - 内容为 SpriteForge 包，或 Live2D 模型加一份默认映射。
   - 安装复用 #191 的无代码包准备（§3），用现有的 `tools/validate_character_pack.py` 和 Live2D 模型检查作为可信校验。
   - 候选接入方式为 Host 全局形象配置中的显式选择。

### 10.3 注意事项

- **版权：** 同人素材会很常见。商店条目要求作者声明素材权利，遇到投诉通过撤回列表（9.1）处理。Live2D Core 由用户自备，包内不得包含。
- **体积：** 形象包常有数十到数百 MB。可信检查器现在的 256 MiB 上限需要为形象包单独评估；商店产物放在 GitHub Releases。
- **性能：** 贴图内存计入现有的纹理预算与采样设置；切换形象时要释放旧贴图。
- **声线不在此列：** 它涉及声优和角色声音的权利，需要单独定好政策后再考虑。

### 10.4 当前只保留关闭声明

- 类型表已包含关闭的 `visual_pack` 声明，原因是需要形象包导出的语义绑定契约。
- 没有因此实现形象包读取或授予安装权限；真正开放须另行设计与验收。

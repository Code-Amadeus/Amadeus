## 2. 已完成的插件基础及保留边界

- 已开放 TTS、MCP、Skill、数据主题；安装一次后选择贡献或绑定兼容 Agent。只有一套安装/更新/卸载管理器。
- Electron main 拥有安装事务、配置、加密凭据与期望状态；Python 拥有启动准入；TTS 用独立 Runner；MCP/Skill 仍由各原生 owner 消费。
- TTS/MCP/Skill 配置与启停在后端重启时生效。纯主题即时生效；混合包使用已加载快照，整包版本在重启时切换。没有扩展 TTS 热交接或对 pipeline 的通用热切换改造。
- 停用/卸载混合包立即关闭前端准入；旧后端可能仍待停止。保存成功、明确接受/拒绝、未确认、健康状态和物理清理必须区分。
- 明确拒绝可结案但不记为已加载；无效、缺失、重复或无法读取的回执仍待确认。旧回执不能清除较新的修改。
- `permissions.host` 必须为空，不保存 Grant 记录。Runner 环境用白名单；原生 Agent 保留自身契约。这不是恶意第三方程序的 OS 沙箱。
- 主题 v0 仅支持 PNG/JPEG，校验实际解码和绘制对比度，提供原生恢复入口。
- MiMo 不支持日语，示例只声明英语；英语实机验收仍待办。Fish 有一次日语真实合成证据，但不是全场景听感认证。`speed` 是建议值，不要求复现 GPT-SoVITS 节奏。
- 内置 MiMo 未移除；迁移与移除另行安排，不是启动记忆设计的前置条件。

剩余限制：混合包旧引用释放后没有自动启动回滚；跨平台 GUI、自然语音、DSH stdout 和 Windows ACL 的资格范围没有因 CI 通过而扩大。完整来源和验收边界见 Host profile。

## 4. M0：Host 内置、有来源的跨会话召回

### 4.1 用户价值与最小范围

第一批证明：在同一个 Project 的新会话中，能找到此前 Session、Work 或 Artifact 中相关的事实，并说明来源。
使用现有 Host 读取接口，不新建第二本 Work 事实库，不把最近窗口里已有的对话再读一遍当作交付成果。

Draft 首批不开放个人跨会话召回；它已有近期历史。个人共享信息与角色共同经历的边界先由 M2 定义。
角色 RAG 是角色参考资料，不应自动解释成用户记忆或角色亲历。

### 4.2 注入与失败边界

- 当前 `server/cooperative_provider_loop.py` 的 `role_reference` 在 `_decide` 中追加到 system，调用处没有独立的检索 deadline；这是当前代码事实，不是新记忆入口的既定设计。
- M0 的结果进入现有 turn frame 中独立、带来源的参考字段，放在历史之后；首轮和后续轮均不写入 system，不伪造历史消息，不改角色身份或执行权。
- 这样可以将召回证据与稳定的人设/指令分开，允许下一轮纠正、排除和撤回，并避免在 system 前缀中引入每轮检索变化。缓存收益须按实际请求测量，不能仅凭字段位置承诺命中率。
- 用现有 turn/admission 和 Host 绑定身份检查 Project、角色、Session、取消状态；检索完成后再核对，晚到或归属变化的结果丢弃。
- 每源与总结果均有长度预算和截止时间；超时/异常返回空参考并留下可诊断原因，普通回复继续。
- 限制仍在执行的查询数量；线程等待超时并不意味着底层查询已终止，不能每轮无限堆积后台查询。
- 与已有 frame 的 `context`、`work_tasks`、`retained_contexts` 按稳定来源去重；同一事项以 Host 事实为准，模型摘要只是派生参考。
- 无来源或旧记录缺少逐条时间时标明未知，不用 Session 文件时间冒充事实发生时间。先证明有界搜索有用，再决定索引或向量存储。

### 4.3 最小验收

| 情景 | 应见结果 |
|---|---|
| 同 Project 的新会话追问之前交付/决定 | 返回相关事实及可追溯来源，不创建重复 Work |
| 其他 Project/角色或未经授权的 Draft 历史 | 不返回、不扩大范围 |
| 无命中、检索异常、超时 | 主对话继续，不捏造记忆 |
| 查询期间切换归属或取消；迟到结果返回 | 不进入当前 turn |
| 账本事实已更新、来源不存在或已被排除 | 不用陈旧文本覆盖当前事实；去重、失效或排除有效 |
| 召回文本含“忽略规则”等指令 | 只作为带来源资料，不授予执行权或修改角色规则 |
| 启用/禁用 M0；未命中 | 原有角色、语言锁、Chat/Work 流程保持可验证行为 |

## 5. M2：Host 显式记忆

提供用户主动的“记住”、查看、纠正、遗忘。先决定用户级共享偏好、角色关系/共同经历、Project 事实各自的作用域、优先级和保存规则，再开放 Draft 跨会话召回。

Host 拥有记忆身份、持久化范围和用户操作入口。查看时显示来源与适用范围；纠正后的事实替换旧的有效记忆；遗忘后，缓存、在途结果和派生索引都不能将其恢复。重启或重建索引必须保持这些效果。
“忘记一条记忆/排除来源”不自动删除原始 Session/Work 账本；删除原始记录是另一项明确操作。保留源记录时也必须保证被排除内容不会再次被召回。

验收覆盖范围隔离、纠正/遗忘与在途查询竞争、重启、索引重建、过期/冲突事实、来源失效和用户可见管理。自动抽取、人格演化、作息与主动对话不在 M2 内。

## 6. M1：外部记忆来源

在 M0/M2 已证明作用域和管理语义后，再修订 `context_source` 契约并做真实外部适配器。
当前 Host 仍拒绝 `context_source`/`observer`；Notes MCP 自己保存笔记，不代表拥有 Amadeus 历史或记忆授权。

开放前必须共同明确：

1. Host 授予的作用域与稳定不透明引用，不让包自行指定任意原始 id 扩大范围。
2. 有界、只读、可撤销的来源接口；不把 Host 数据库或 Session 路径作为插件 API。该契约限制不是对恶意程序 OS 访问的沙箱保证。
3. 查询、列表、纠正、遗忘、导出使用同一套作用域规则；源更新/删除能使缓存和派生内容失效。
4. 遗忘成功后清理旧在途结果；重启/重建不能复活内容；卸载保留/删除数据的选择如实呈现。
5. 来源仅关联到实际被接受的 turn；不能把每次消息 append 或 observer 事件当作永久记忆同意。

M1 不预造第二套身份或事实 schema，不以安装成功替代运行和撤销验收。

# 正常 Host 的已提交来源投递

这一步让桌面 Host 可以把当前会话提交的原话按版本投递给同一个 Eidema 库，为内部与公开题的同版查阅提供来源底座。候选基于 `7e931982`，使用已锁定的 schema 19 wheel。默认关闭 `AMADEUS_MEMORY_SOURCE_RUNTIME_ENABLED`。开启时，Host 在 SDK 可用后订阅正常 Session 提交，关闭时解除订阅并等当前存储操作退出。

## 来源规则

- Session 是原话、说话者、记录时钟、消息修订和会话世代的权威。通知只带 Session 路径，SDK 接收游标是重启恢复进度。未登记过的既有对话须另行导入，开启开关只登记新提交的内容。
- 一条来源按提交时的角色私有或 Work 项目范围保存。有来源后改变项目不会迁移此前的来源。会话修改、撤回和删除即使发生在投递暂停时也由已登记的 Session 保存事实。
- 同一 SDK 用已有维护接口按页接收版本，核对当前文件里的版本与用途，再建立 FTS 投影。语义索引复用已有的模型执行槽。来源的新授权限于显式查阅，此阶段尚未接通面向用户的原话消费入口。

## 本机核对

隔离用例经过真实 Host 启动、Session 提交和 SDK，不直接插入来源表。覆盖旧聊天不开启回填、另一会话查找、角色和项目权限、助手实答截断产生新修订、控制片段退出发现索引、停止期间删除以及重开。表中语义对照用固定测试嵌入验证中日跨会话来源能进入同一个向量索引，不计真实嵌入或角色实答分数。

## 内部和公开的质量判据

**19/24、零严重误用**是历史研究版的质量参照。**18/24**是桌面 A 的当前入口对照，保留该数字是为了观察后续改动的增量。两次使用的角色底稿、语言锁和时钟装配有差异，各位置只答一次。桌面 A 失去周宁引语归属，并新增一次榆室严重跨场误用。18/24 的原考虑线不替代逐题质量回归。

同一次候选比较固定 Host 入口、角色和模型参数、可见来源和八组预算，让内部 36 轮和已见的公开开发题分别作同题 A/B。依次记录正确原话出现在候选、完整依据入模和最终正确使用。内部逐道核对历史 19 个正确项及更正、遗忘、安静三个各六项的控制。公开另报时序、多会话、更新及未知，不跨题集相减。只把补回的实际答复计为质量收益，零新增严重误用是资格条件。45 道公开未见题在候选冻结后单独验收。

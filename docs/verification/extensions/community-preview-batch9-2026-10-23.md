# 插件投稿流程补充验收（2026-10-23）

本轮范围由用户收敛为本地 Git 演练和草稿 PR 准备，不新建 GitHub 测试仓、不公开发布、不合并主线。随后用户选择保留运行中的 Amadeus，因此只执行新增维护端工具验收，不重跑桌面。

## 对外审的判断

外审引用的是 F: 主工作区和公开仓库 main；它关于“主线没有在线商店/公开目录”的观察成立，但不能据此判断实验分支只有本地安装。实验分支的 S0–S2、完整本地 Git→HTTPS→桌面链路已在第八批验证。真实缺口是作者投稿与维护者发布交接，不需要重写下载器或增加作者账号系统。

采纳：短投稿指南/模板、首次与更新/转移的授权依据、非作者最新实质修改审核、同一个 PR 的返修、发布负责人交接、候选与实际分发验收、同摘要换地址及安全反馈说明。实现不新增目录或 manifest 字段，不新增数据库或持久状态。

按用户要求减负：
- 作者只运行一个预检命令，发一个 PR；四项简短信息，复用 README、发布说明、测试日志。
- 初次确认归属/权利，更新复用已有证据；只有控制或权利变化才补证据。有歧义时才用挑战证明。
- 作者不填写虚构审核人，也不组织多个审核角色。维护者指定一个对接人，负责评审交接和发布；标签只是可选展示。
- 返修留在原 PR；仅实质变化使相关检查/审批失效。文字修正不要求重新做整套运行资格。
- 维护者准备第二个、可批量的索引发布 PR。复杂度由工具和维护者承担。

调整两条审计建议：不为展示缓存增加独立 TTL，因为现有安装器每次商店安装都会强制刷新官方索引；不要求每次安全发布重新下载全部旧包，否则原地址失效会阻断封禁。新上架、恢复收录、解封和换 URL 的产物做新下载校验，撤回/封禁或未变化产物的跳过范围写进回执。

## 实现与边界

协议仓新增 catalog/SUBMISSION.md、短 PR 模板、preflight_submission.py 和 verify_publication.py。
预检复用固定 Host check-wheel 与同一 check_policy：报告格式/Host 接受、首版政策、待人工/运行审核；通用 Host 拒绝时不猜测“包格式通过”。Notes 通过目录政策，Fish Audio 可被 Host 接受但目录政策拒绝。工具不导入插件代码，也不会生成“已审核”结论。

分发验收读取指定、已检查的候选/官方索引原始字节，匹配后用新临时缓存验证新增可分发/换地址产物的摘要和大小。旧但合法的索引也不能冒充本次发布。重复使用现有 HTTPS、重定向、体积和摘要规则。

Host 演练在首次提交中故意写错 wheel 摘要，正式 CI 拒绝；修订同一份输入并重检后才推进本地模拟 approved ref。六个发布阶段均验证 candidate-index 与实际 index；它们仍为明确模拟的审核/批准，不能代表 GitHub 身份或独立人类审核。

运行入口增加 --publisher-only，不启动 Electron、不占用 17777。默认完整桌面演练仍保留；公开 bootstrap 和运行契约/pin 未变。

## PR 准备和仍需实际验证的部分

建议按仓库准备两份草稿：协议仓收录规范/工具/模板，Host 仓现有商店实现与演练。当前没有现存商店 PR，本轮保留本地 PR 正文与提交/差异信息，不推远端。

只读模拟发现 Host 实验分支与当前 main 5382b329 存在旧依赖来源和验收文件冲突：main 已合入 #252 的后续版本，不能把旧实验依赖重新推成新的升级。实际创建 Host PR 前必须在隔离集成分支采用 main 的已合入依赖修复，保留商店变化，重新跑集成检查。此处未修改 main，也未把冲突模拟当作已完成集成。

真实 GitHub 分支保护、非作者审批、Actions 凭据/公共 pin 可达性、公开地址可用性，以及独立作者仅凭文档完成投稿仍在发布前验证。用户已明确本轮不做远端测试仓；流程固定不等于这些环境条件已验证。无需首版加入评分、签名、自动升级、通用配置迁移或作者后台。
